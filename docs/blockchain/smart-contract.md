# Smart Contract: CredentialRegistry.sol

Location: `blockchain/contracts/CredentialRegistry.sol`

## What is stored on-chain (and what is not)

On-chain, per credential:

```text
credentialId      (string)   application-generated unique ID, e.g. "CRED-ab12cd34ef56"
credentialHash    (bytes32)  SHA-256 digest of the off-chain document
issuer            (address)  wallet that registered the credential
issuedAt          (uint256)  block timestamp
revoked           (bool)
```

**Never stored on-chain:** the certificate file itself, names, Aadhaar
numbers, phone numbers, emails, addresses, passwords, or any other PII. If a
future feature needs more metadata attached to a credential, it should be
referenced by a database ID or an off-chain metadata URI — not embedded
on-chain. See `architecture.md` for the reasoning.

## Access control

Built on OpenZeppelin's `AccessControl`:

- **`DEFAULT_ADMIN_ROLE`** — set at deploy time to the deployer/admin
  address. Can authorize or revoke issuers. Cannot register or revoke
  credentials unless also granted `ISSUER_ROLE`.
- **`ISSUER_ROLE`** — granted per-address by the admin via
  `authorizeIssuer(address)`. Only accounts with this role can call
  `registerCredential`. Both issuers and the admin can call
  `revokeCredential`.

This maps directly to the "Admin authorizes issuers; issuers register/revoke
credentials" design in the project spec.

## Functions

| Function | Caller | Purpose |
|---|---|---|
| `authorizeIssuer(address)` | admin only | Grant `ISSUER_ROLE` |
| `revokeIssuer(address)` | admin only | Remove `ISSUER_ROLE` |
| `registerCredential(string credentialId, bytes32 credentialHash)` | issuer only | Create a new credential record. Reverts on duplicate `credentialId`, empty ID, or zero hash. |
| `revokeCredential(string credentialId)` | issuer or admin | Marks a credential `revoked = true`. Reverts if already revoked or not found. |
| `verifyCredential(string credentialId, bytes32 credentialHash) view` | anyone | Returns `true` only if the credential exists, the supplied hash matches, **and** it is not revoked. |
| `getCredential(string credentialId) view` | anyone | Returns the full public record (hash, issuer, issuedAt, revoked, exists). |

## Events

- `CredentialRegistered(string indexed credentialId, bytes32 credentialHash, address indexed issuer, uint256 issuedAt)`
- `CredentialRevoked(string indexed credentialId, address indexed revokedBy, uint256 revokedAt)`
- `IssuerAuthorized(address indexed issuer, address indexed authorizedBy)`
- `IssuerRevoked(address indexed issuer, address indexed revokedBy)`

None of these carry sensitive data — only IDs, addresses, hashes, and
timestamps.

## Duplicate prevention

`registerCredential` checks an internal `exists` flag on the credential
struct before writing, and reverts with
`"CredentialRegistry: credential already exists"` if a `credentialId` has
already been used. IDs are meant to be generated by the backend (this repo
uses `CRED-<12 hex chars>`), so collisions should be effectively impossible
in practice — the on-chain check is a hard backstop.

## Hash conversion (SHA-256 -> bytes32)

The off-chain document hash is computed as SHA-256 (`0x` + 64 hex chars,
i.e. exactly 32 bytes). `bytes32` is exactly 32 bytes, so the conversion is
a direct byte copy with no truncation — see `hex_hash_to_bytes32` in
`backend/blockchain-service/app/blockchain_client.py`.
